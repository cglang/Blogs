闭包不是什么魔法，而是**函数与其词法环境的组合**。要真正理解它，先要看懂作用域链是如何建立的。

## 词法作用域

JavaScript 采用词法作用域：函数能访问哪些变量，在**定义时**就已经确定，而不是调用时。

```js
const value = "outer";

function print() {
  console.log(value);
}

function run() {
  const value = "inner";
  print(); // 输出 outer
}

run();
```

`print` 定义在全局作用域，所以它看到的是外层的 `value`，即使调用发生在 `run` 内部。

## 闭包的定义

当内部函数引用了外部函数的变量，并且这个内部函数在外部函数返回后仍被使用，就形成了闭包。

```js
function createCounter() {
  let count = 0;
  return {
    inc() {
      return ++count;
    },
    get() {
      return count;
    },
  };
}

const counter = createCounter();
counter.inc();
counter.inc();
console.log(counter.get()); // 2
```

`count` 本应在 `createCounter` 执行完后销毁，但因为 `inc` 和 `get` 仍持有对它的引用，这个变量被保留了下来。

## 常见应用

- **数据私有化**：上面的计数器，外部无法直接修改 `count`。
- **函数工厂**：批量生成带有不同配置的函数。
- **防抖 / 节流**：用闭包保存定时器或上次执行时间。

```js
function debounce(fn, delay = 300) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}
```

## 经典陷阱：循环中的 var

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 3 3 3
```

`var` 没有块级作用域，三个回调共享同一个 `i`。改用 `let` 即可每次迭代创建新的绑定：

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 0 1 2
```

## 闭包与内存

闭包会让被引用的变量无法被垃圾回收。长时间持有大对象时，要注意及时释放：

```js
let cache = createHeavyCache();
// 使用完毕后
cache = null;
```

## 小结

1. 作用域在定义时确定，闭包 = 函数 + 词法环境。
2. 闭包适合做封装、函数工厂与状态保持。
3. 它会延长变量生命周期，使用时要关注内存。
